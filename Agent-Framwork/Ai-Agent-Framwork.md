## 1. LangChain

**Definition:** LangChain is a framework for building applications powered by large language models (LLMs). It provides components for prompts, model calls, document processing, retrieval, tools, and agents.

**Example:**

```text
User question
      ↓
Prompt
      ↓
LLM
      ↓
Tool or retrieved data
      ↓
Final answer
```

**Instructions:**

* Use LangChain when you need to connect multiple AI components into an application.
* It supports integrations with many LLM providers, vector stores, document loaders, and tools.
* LangChain can be used for simple LLM calls as well as more complex agent applications.
* Do not assume LangChain automatically makes an application an agent; agents require additional planning/tool-use logic.

## 2. LangGraph

**Definition:** LangGraph is a library for building stateful, multi-step AI and agent workflows using a graph of nodes and transitions.

**Example:**

```text
START
  ↓
Understand Request
  ↓
Choose Tool ──→ Use Tool
  ↓               ↓
Check Result ←────┘
  ↓
END
```

**Instructions:**

* A **state** stores information that the workflow needs while it runs.
* A **node** performs an operation, such as calling an LLM or a tool.
* An **edge** controls which node runs next.
* LangGraph is useful when an agent needs loops, branching, checkpoints, or persistent state.

## 3. CrewAI

**Definition:** CrewAI is a Python framework for building applications where multiple AI agents work together as a team.

**Example:**

```text
Research Agent
      ↓
Find and summarize information
      ↓
Writer Agent
      ↓
Create the final report
```

**Instructions:**

* Give each agent a clear role, goal, and available tools.
* A **Crew** coordinates agents and their tasks.
* Agents can use LLMs and tools to perform assigned work.
* Multi-agent workflows can be more complex and expensive than using a single agent, so use multiple agents only when they provide a useful separation of tasks.

## 4. AutoGen

**Definition:** AutoGen is a Microsoft-originated framework for building AI applications where agents can communicate and collaborate to complete tasks.

**Example:**

```text
User
 ↓
Planner Agent
 ↓
Coder Agent
 ↓
Reviewer Agent
 ↓
Final Result
```

**Instructions:**

* Agents can have different roles and responsibilities.
* Agents can exchange messages and delegate work.
* It is useful for workflows that benefit from multiple specialized agents.
* The exact APIs and recommended architecture can change between AutoGen versions, so follow the documentation for the version you use.

## 5. Core Architecture and Model I/O

**Definition:** Core architecture describes how an AI application connects its components, while model I/O describes the information sent to and returned from an LLM.

**Example:**

```text
Application
    ↓
Prompt + Input
    ↓
LLM
    ↓
Model Output
    ↓
Application Logic
```

**Instructions:**

* **Input** can include user messages, system instructions, documents, or tool results.
* **Output** is usually text or structured data generated by the model.
* Frameworks provide reusable components for connecting models with application logic.
* Keep model-specific code separated when possible so providers can be changed more easily.

## 6. LangChain Expression Language

**Definition:** LangChain Expression Language (LCEL) is a way to compose LangChain components into runnable workflows using a simple pipeline style.

**Example:**

```python
chain = prompt | model | parser

result = chain.invoke({"question": "What is RAG?"})
```

**Instructions:**

* The `|` operator connects runnable components in sequence.
* Each step receives the output of the previous step.
* LCEL can make simple chains easier to read and reuse.
* Modern LangChain applications may also use LangGraph for more complex agent workflows.

## 7. Retrieval and Document Engineering

**Definition:** Retrieval and document engineering is the process of preparing documents and finding relevant information for an LLM.

**Example:**

```text
PDF
 ↓
Load Document
 ↓
Split into Chunks
 ↓
Create Embeddings
 ↓
Store in Vector Database
 ↓
Retrieve Relevant Chunks
 ↓
Send Context to LLM
```

**Instructions:**

* Documents often need to be loaded, cleaned, and split into useful chunks.
* Embeddings convert text into vectors that can be searched for semantic similarity.
* Retrieval helps provide relevant external information to the LLM.
* Poor chunking or retrieval can lead to incomplete or incorrect answers.

## 8. Memory and State Management

**Definition:** Memory and state management means storing information that an AI application needs across steps or interactions.

**Example:**

```text
User: My name is Bob.
        ↓
State / Memory
        ↓
Later:
AI: Welcome back, Bob.
```

**Instructions:**

* **State** usually represents information needed during a workflow.
* **Memory** can store information across interactions, depending on the application's design.
* LangGraph provides explicit state management for graph-based workflows.
* Do not treat every conversation history as permanent memory; storage and persistence must be designed separately.

## 9. Tool Integration and Agents

**Definition:** Tool integration allows an AI application to call external functions, APIs, databases, search systems, or other software.

**Example:**

```text
User: What is 25 × 18?
        ↓
Agent
        ↓
Calculator Tool
        ↓
450
        ↓
Final Answer
```

**Instructions:**

* A tool gives an agent an ability that the LLM does not have directly.
* Common tools include web search, calculators, databases, APIs, and custom Python functions.
* An agent can decide when a tool is needed and use its result.
* Validate tool inputs and outputs, especially when tools can modify data or perform external actions.

## 10. Observability and Evaluation

**Definition:** Observability means tracking what an AI application does, while evaluation means measuring whether its outputs are correct, useful, and reliable.

**Example:**

```text
User Input
   ↓
Agent
   ↓
Tool Call
   ↓
LLM Response
   ↓
Logs + Evaluation
```

**Instructions:**

* Log important steps such as model calls, tool calls, errors, latency, and token usage.
* Use evaluation datasets or test cases to check application quality.
* Test both normal and failure scenarios.
* Avoid logging sensitive user information unless it is necessary and properly protected.
